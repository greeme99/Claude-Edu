## 1. 벽은 능력이 아니라 입구였어요

<LessonLink id="TH-04" />에서 **Product Overhang**을 이야기했어요. 모델의 능력은 이미 충분한데, 그 능력을 꺼내 쓸 소프트웨어가 없어서 잠들어 있는 상태예요. <Term id="T-HARNESS" />가 그 자물쇠를 열었고, Claude Code가 그 첫 증명이었죠.

그런데 여기에 두 번째 오버행이 남아 있었어요. **하네스는 있는데, 그 하네스에 접근할 수 있는 사람이 개발자뿐**이었다는 것이에요.

에이전트 루프를 돌리려면 터미널을 열고, npm으로 설치하고, `cd`로 폴더를 옮기고, `claude`를 입력해야 했어요. 계약서 40건에서 갱신 조항을 뽑아야 하는 법무 담당자, 매주 월요일 다섯 개 시트를 하나로 합쳐야 하는 재무 담당자에게 이 절차는 기술 장벽이 아니라 **문화적 장벽**이었어요. 그들의 업무는 이미 파일과 폴더 위에 있었는데, 그 파일에 에이전트를 붙일 방법이 없었던 거예요.

<Callout type="key">
Cowork를 한 문장으로 정의하면 이래요. **"Claude Code를 움직이는 것과 같은 에이전트 아키텍처를, 터미널 없이(no terminal required) 지식 노동에 적용한 것."** 새로운 모델도, 새로운 프로토콜도 아니에요. **입구가 바뀐 것**입니다.
</Callout>

## 2. 세 번째 표면

이제 Claude에는 성격이 뚜렷하게 다른 세 개의 표면이 있어요.

| | **Chat** | **Claude Code** | **Cowork** |
|---|---|---|---|
| 형태 | 대화 | 터미널 CLI | 작업 세션 |
| 주 사용자 | 누구나 | 개발자 | 지식 노동자 |
| 다루는 대상 | 텍스트 | 코드베이스 | 파일·폴더·앱 |
| 루프가 도는 곳 | (루프 없음) | 내 컴퓨터 | 클라우드 |
| 산출물 | 답변 | 커밋된 코드 | 문서·시트·덱·아티팩트 |
| 적합한 일 | 초안, 브레인스토밍 | 코딩 | 앱을 넘나드는 지식 업무 |

Anthropic이 제시하는 선택 기준은 단순해요. **대화로 끝나면 Chat, 코드면 Claude Code, 파일과 앱을 넘나드는 일이면 Cowork.**

여기서 중요한 것은 세 표면이 **같은 기반 위에 있다**는 점이에요. 세 번째 표면은 새로운 능력을 추가한 것이 아니라, 이미 있던 능력에 **다른 문을 낸 것**이에요.

## 3. 계층은 그대로예요

<LessonLink id="TH-05" />에서 5개 계층을 그렸어요. 프롬프트 → 컨텍스트 엔지니어링 → 하네스 → MCP → Skills. Cowork는 이 계층을 갈아엎지 않아요. **같은 계층 위에 앉아 있고, 각 계층의 이름표만 사용자 언어로 바뀌어 있어요.**

<div className="stratum">

| 계층 | 개발자 표면(Claude Code) | 지식 노동 표면(Cowork) |
|---|---|---|
| 프롬프트 | 대화 입력 | 대화 입력 |
| 컨텍스트 | `CLAUDE.md` | 전역 지침 · 프로젝트 지침 · 폴더 지침 |
| 하네스 | 에이전트 루프 + 도구 | 동일 (Gather · Act · Verify) |
| 도구 연결 | MCP 서버 (`claude mcp add`) | **커넥터** (Customize 패널에서 켜기) |
| 절차 지식 | `.claude/commands/*.md` | **스킬** (`/스킬이름` 또는 "이걸 스킬로 만들어줘") |
| 배포 | Git 커밋 | **플러그인** (팀 마켓플레이스) |

</div>

<Callout type="key">
같은 <Term id="T-MCP" />, 같은 <Term id="T-SKILLS" />, 같은 <Term id="T-LOOP" />예요. 달라진 것은 **설치가 명령어에서 토글로, 파일 편집이 대화로** 바뀐 것뿐이에요. 이것이 <LessonLink id="TH-05" />에서 말한 "도구 생태계의 민주화"가 실제로 구현된 모습입니다.
</Callout>

## 4. 루프가 클라우드에서 돌아요

Cowork의 구조에서 가장 중요한 단 하나의 사실은 이거예요. **세션이 내 컴퓨터가 아니라 Anthropic의 서버에서 실행돼요.** <Term id="T-CLOUDAG" />의 형태예요.

이것이 만드는 결과가 큽니다.

**첫째, 세션이 나보다 오래 살아요.** 앱을 닫아도 작업이 계속돼요. 노트북을 덮고 나가도 30분짜리 작업이 진행되고 있어요. 데스크톱에서 시작해 모바일에서 확인하고 웹에서 마무리할 수 있어요. 세션이 기기가 아니라 **계정에 붙어 있기** 때문이에요.

**둘째, 로컬 파일은 다리를 건너야 해요.** 클라우드에서 도는 세션이 내 컴퓨터의 파일을 만지려면 데스크톱 앱이 그 다리 역할을 해요. 그래서 **연결된 폴더의 파일은 데스크톱 앱이 열려 있는 동안에만** 읽고 쓸 수 있어요. 앱을 닫으면 세션은 계속 돌지만 로컬 파일에는 손이 닿지 않아요.

**셋째, 스케줄 작업이 가능해져요.** 매주 월요일 9시에 도는 작업은 내 컴퓨터가 켜져 있는지와 무관하게 실행돼요. 다만 같은 이유로, **스케줄 작업은 로컬 폴더에 묶일 수 없어요.**

| 표면 | 로컬 파일 | 브라우저 | 컴퓨터 사용 |
|---|---|---|---|
| 데스크톱 | 직접 접근 | 내장 브라우저 | 가능 |
| 웹 · 모바일 | 데스크톱 앱이 켜져 있을 때만 | 데스크톱 앱이 온라인일 때만 | 불가 |
| Chrome 사이드 패널 | 데스크톱 앱 경유 | 열려 있는 탭 | 불가 |

<Callout type="warn">
"세션은 클라우드에, 파일은 내 컴퓨터에" — 이 분리를 이해하지 못하면 "왜 갑자기 파일을 못 읽지?"라는 상황을 계속 만나게 돼요. 답은 대부분 **데스크톱 앱이 닫혔거나 잠들었다**입니다.
</Callout>

## 5. 브라우저 — 커넥터가 없는 곳으로 가는 길

<Term id="T-MCP" />는 강력하지만 한계가 있어요. **커넥터가 없는 시스템**은 어떻게 하죠? 사내 레거시 포털, 커넥터를 제공하지 않는 SaaS, 관공서 사이트 같은 곳이요.

Cowork는 두 가지 답을 가지고 있어요.

| | **내장 브라우저** | **Claude in Chrome** |
|---|---|---|
| 정체 | 데스크톱 앱 안의 Claude 전용 브라우저 | 내 실제 Chrome |
| 내 탭·북마크·비밀번호 | 보지 않음 | 내 세션을 그대로 사용 |
| 적합한 일 | 통째로 위임하는 조사·수집 | 이미 로그인해 열어둔 페이지 |
| 설치 | 불필요 | 확장 프로그램 필요 |

내장 브라우저는 다른 브라우저에서 로그인을 가져올 수 있지만, **은행·이메일·SSO 사이트는 기본적으로 제외**돼요. 커넥터가 정식 통로라면 브라우저는 **비상구**예요. 정식 통로가 있으면 그쪽이 항상 더 안전하고 빠릅니다.

<Callout type="warn">
브라우저와 커넥터는 둘 다 **외부 콘텐츠를 컨텍스트로 끌어들이는 통로**예요. 웹페이지에 심어둔 지시문이 에이전트의 행동을 조종하는 <Term id="T-PI" /> 문제가 여기서 실제 위험이 됩니다. 에이전트가 읽은 것은 **데이터이지 명령이 아니라는** 원칙이 하네스 수준에서 지켜져야 해요.
</Callout>

## 6. 권한이 제품이 되었어요

<LessonLink id="TH-04" />에서 하네스의 조건으로 **검증**을 강조했어요. 검증이 빠진 루프는 치명적이라고요. Cowork에서 이 원칙은 **승인 모드**라는 눈에 보이는 형태로 제품 표면에 올라왔어요.

| 모드 | 동작 | 적합한 상황 |
|---|---|---|
| **수동(Manual)** | 매 행동 전에 사람에게 묻기 | 프로덕션 데이터, 되돌리기 어려운 작업 |
| **자동(Auto)** | 스스로 안전성을 점검한 뒤 실행 | 검증 가능한 반복 작업 |
| **건너뛰기(Skip)** | 자동 점검 없음 | 모든 행동을 완전히 신뢰할 때만 |

여기에 **삭제 보호**가 별도로 걸려 있어요. 파일을 영구 삭제하려면 명시적 허가가 따로 필요해요. 그리고 접근 범위는 **내가 연결한 폴더 안으로 한정**돼요. 연결하지 않은 폴더는 존재 자체가 보이지 않아요.

<Callout type="key">
<LessonLink id="PR-11" />에서 배운 원칙이 그대로 적용돼요. **자율성은 검증 가능성에 비례해서 높이는 것.** 코드에서 그 검증이 테스트 커버리지였다면, 지식 업무에서는 "결과가 맞는지 사람이 확인할 방법이 있는가"예요. 확인할 방법이 없는 작업에 자동 승인을 거는 것이 가장 위험한 조합입니다.
</Callout>

## 7. 결과물이 대화 밖으로 나와요

Chat에서 AI에게 표를 요청하면 채팅창 안에 표가 그려져요. 그걸 엑셀로 옮기는 건 사람의 일이었죠. Cowork에서는 이 마지막 구간이 사라져요.

- 수식이 들어간 스프레드시트, 발표용 덱, 서식이 잡힌 문서를 **파일로** 만들어요
- 만든 파일을 **연결된 폴더에** 그대로 써요 — 다시 저장할 필요가 없어요
- 다시 열어볼 결과물은 <Term id="T-ARTIFACT" />로 게시돼요. 자기 URL을 가지고, 대화가 끝나도 살아남고, 다시 갱신할 수 있어요

<LessonLink id="TH-04" />의 표현을 빌리면, 채팅에서 30분 걸리던 일이 에이전트에서 3분이 되는 이유는 모델이 빨라져서가 아니라 **사람이 병목이던 구간이 자동화**되었기 때문이에요. Cowork에서 사라진 병목은 **"AI의 답을 실제 산출물로 옮겨 적는 시간"** 입니다.

## 8. 남는 것과 남지 않는 것

이 표면이 무엇을 바꾸고 무엇을 바꾸지 않는지 분명히 해둘 필요가 있어요.

**바뀐 것** — 에이전트를 쓰기 위한 진입 비용. 터미널·설치·경로 지식이 필요 없어졌어요. 도구를 만드는 일도 마크다운을 쓸 줄 아는 사람이면 충분해요. 의사가 진료 프로토콜을, 변호사가 계약 검토 절차를 스킬로 패키징할 수 있어요.

**바뀌지 않은 것** — <Term id="T-HALL" />은 여전히 구조적 특성이고, <Term id="T-JAGGED" />는 여전히 들쭉날쭉해요. 컨텍스트 설계가 결과 품질을 좌우한다는 원리도 그대로예요. **결정적으로, 판단의 책임은 여전히 사람에게 있어요.** Anthropic 자신도 이 제품을 "인간의 감독을 전제로 설계했고, 중대한 결정은 사용자에게 남는다"고 설명해요.

<Callout type="q">
그래서 질문은 "AI가 이 일을 할 수 있는가"에서 **"이 일의 결과를 내가 검증할 수 있는가"** 로 옮겨가요. 검증할 수 없는 일을 자동화하는 것이 가장 나쁜 시나리오라는 원칙은, 표면이 셋으로 늘어나도 변하지 않습니다.
</Callout>

<Callout type="key">
1. **Cowork는 새 모델이 아니라 새 입구예요** — Claude Code와 같은 에이전트 아키텍처, 터미널만 걷어낸 것
2. **세 표면의 분업** — 대화는 Chat, 코드는 Claude Code, 파일·앱을 넘나드는 일은 Cowork
3. **계층은 그대로** — MCP는 커넥터로, 스킬 파일은 스킬로, CLAUDE.md는 지침으로 이름만 바뀌었어요
4. **세션은 클라우드, 파일은 내 컴퓨터** — 이 분리가 지속 실행과 스케줄을 가능하게 하고, 동시에 로컬 접근을 데스크톱 앱에 묶어요
5. **권한이 제품 표면으로** — 승인 모드 3단계, 삭제 보호, 연결된 폴더로 한정된 접근 범위
6. **자율성은 검증 가능성에 비례** — 결과를 확인할 방법이 없는 일에 자동 승인은 최악의 조합
</Callout>
