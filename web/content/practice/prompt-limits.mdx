## 준비물

- ChatGPT(무료) 또는 Claude(무료)
- 웹 브라우저, 메모장
- **시간 여유** — 대화를 10턴 이상 이어갈 거예요

## 1. 프롬프트의 세 가지 벽

<LessonLink id="PR-01" />에서 맥락·제약조건·형식으로 프롬프트를 구조화하는 법을 배웠어요. 오늘은 한 걸음 더 나가서, **그 기법이 통하지 않는 지점**을 직접 확인합니다. 한계를 모르면 한계 안에서만 헤매게 되거든요.

| 한계 | 원인 | 증상 |
|---|---|---|
| **지시 망각** | 대화가 길어지면 초기 지시가 밀려남 | 규칙을 점점 무시함 |
| **환각** | 모르는 정보를 확률적으로 생성 | 자신 있게 틀린 답을 줌 |
| **컨텍스트 부재** | AI가 배경 정보 없이 추측 | 엉뚱한 방향으로 답변 |

## 2. 실습 A — 지시 망각 체험

<Step n={1} title="시스템 프롬프트에 규칙 설정하기">

새 대화를 열고 첫 메시지에 아래 규칙을 입력하세요. 이것이 이 대화의 <Term id="T-SYSP" /> 역할을 해요.

```
이 대화에서 너는 아래 규칙을 반드시 지켜야 해.

규칙:
1. "혁신적"이라는 단어를 절대 사용하지 마
2. 모든 답변에 구체적인 수치(%, 금액, 기간 등)를 반드시 포함해
3. 답변은 항상 3문장 이내로 작성해
4. 모든 답변의 끝에 "[규칙 준수]"라고 표시해

이해했으면 "규칙을 확인했습니다"라고 답해.
```

</Step>

<Step n={2} title="5턴까지 규칙 준수 확인하기">

자연스러운 대화를 이어가세요. 아래는 예시예요.

```
턴 1: "한국 스타트업 시장의 현황을 알려줘"
턴 2: "그중에서 가장 성장이 빠른 분야는?"
턴 3: "AI 스타트업이 투자받으려면 뭘 준비해야 해?"
턴 4: "실패하는 스타트업의 공통점은?"
턴 5: "성공 사례를 하나 들어줘"
```

각 턴에서 네 가지 규칙이 지켜지는지 체크하세요.

| 턴 | 혁신적 금지 | 수치 포함 | 3문장 이내 | 규칙 준수 표시 |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |
| 4 | | | | |
| 5 | | | | |

보통 5턴까지는 잘 지켜요. AI가 "규칙을 기억하고 있는 상태"이기 때문이에요.

</Step>

<Step n={3} title="10턴 넘긴 후 같은 규칙 확인하기">

주제를 조금씩 바꾸면서 10턴을 넘겨보세요.

```
턴 6:  "한국의 교육 시스템 문제점은?"
턴 7:  "AI가 교육에 미치는 영향은?"
턴 8:  "온라인 교육 플랫폼 추천해줘"
턴 9:  "자기계발 책 3권 추천해줘"
턴 10: "시간 관리 방법 알려줘"
턴 11: "한국의 부동산 시장 전망은?"
턴 12: "투자 초보가 알아야 할 것은?"
```

흔히 나타나는 붕괴 순서는 이래요.

1. "[규칙 준수]" 표시가 먼저 사라져요 (가장 약한 규칙)
2. 3문장 제한이 풀려요 (자연스러운 응답 본능이 이김)
3. "혁신적"이라는 단어가 슬쩍 등장해요
4. 수치 포함 규칙이 마지막까지 남는 경우가 많아요

이것이 **지시 망각(instruction drift)** 이에요. 대화가 길어지면 AI의 <Term id="T-ATTN" />이 초기 지시에서 점점 멀어져요. 첫 위반이 언제 나타나는지 기록해두세요. 보통 7~10턴 사이예요.

</Step>

## 3. 실습 B — 컨텍스트 유무 비교

<Step n={4} title="컨텍스트 없이 질문하기">

새 대화를 열고 입력하세요.

```
우리 회사 상황에 맞는 마케팅 전략을 3가지 제안해줘.
```

아마 "소셜 미디어 마케팅을 강화하세요", "콘텐츠 마케팅에 투자하세요" 같은 답이 나올 거예요. 맞는 말이지만 **모든 회사에 해당되는 일반론**이에요. 검색 엔진 결과와 다를 게 없죠.

</Step>

<Step n={5} title="컨텍스트를 제공하고 같은 질문하기">

새 대화를 열고, 이번에는 상세한 컨텍스트를 먼저 제공하세요.

```
우리 회사 정보:
- 업종: B2B SaaS (프로젝트 관리 도구)
- 직원 수: 15명
- 현재 고객: 국내 중소기업 50곳
- 월 매출: 3,000만 원
- 마케팅 예산: 월 300만 원
- 주요 경쟁사: Notion, Monday.com
- 강점: 한국어 UI, 국내 법인 지원
- 약점: 영어 지원 미비, 글로벌 인지도 없음
- 목표: 6개월 내 고객 100곳 달성

이 상황에 맞는 마케팅 전략을 3가지 제안해줘.
각 전략에 예상 비용과 기대 효과를 포함해줘.
```

| 비교 항목 | 컨텍스트 없이 | 컨텍스트 포함 |
|---|---|---|
| 구체성 | 일반론 | 우리 회사 맞춤 |
| 실행 가능성 | 낮음 | 높음 |
| 수치 포함 여부 | 거의 없음 | 예산/기간 반영 |
| 바로 적용 가능 여부 | 불가 | 검토 후 적용 가능 |

프롬프트 기법만으로는 **정보의 부재**를 메울 수 없어요. AI에게 판단 재료를 주는 것, 이것이 <Term id="T-CE" />의 시작이에요.

</Step>

## 4. 실습 C — 환각 유도 체험

<Step n={6} title="존재하지 않는 정보 질문하기">

새 대화를 열고 입력하세요. 정답이 존재하지 않는 질문이에요.

```
김소월 시인의 세 번째 시집 제목이 뭐야?
```

김소월은 생전에 시집을 한 권(『진달래꽃』, 1925)만 출간했어요. 세 번째 시집은 존재하지 않아요. 하지만 AI는 높은 확률로 그럴듯한 제목을 지어내요. 이것이 <Term id="T-HALL" />이에요.

한 가지 더 시도해볼게요.

```
"Quantum Synapse Architecture"라는 논문의 주요 발견을 요약해줘.
이 논문은 2024년 Nature에 실렸어.
```

이 논문은 존재하지 않아요. 하지만 AI는 마치 읽어본 것처럼 저자 이름, 실험 방법, 결론까지 지어낼 수 있어요.

왜 이런 일이 벌어질까요? AI에게는 "모른다"고 답하는 것보다 "그럴듯한 답을 생성하는 것"이 확률적으로 더 자연스럽기 때문이에요. **AI는 검색 엔진이 아니라 확률적 텍스트 생성기예요.**

</Step>

<Callout type="warn">
환각은 AI의 버그가 아니라 **구조적 특성**이에요. 프롬프트를 아무리 잘 써도 환각 가능성을 0으로 만들 수는 없어요. 이론적 배경은 <LessonLink id="TH-02" />에서 다룹니다.
</Callout>

## 5. 한계의 지도 그리기

| 한계 | 프롬프트로 해결 가능? | 해결 방향 | 다루는 차시 |
|---|---|---|---|
| 지시 망각 | 부분적 | 시스템 프롬프트, 컨텍스트 설계 | <LessonLink id="PR-06" /> · <LessonLink id="PR-07" /> |
| 환각 | 완전 해결 불가 | 출처 요구, <Term id="T-RAG" />, 검증 루프 | <LessonLink id="TH-02" /> · <LessonLink id="PR-11" /> |
| 컨텍스트 부재 | 부분적 | 컨텍스트 엔지니어링 | <LessonLink id="PR-05" /> · <LessonLink id="PR-06" /> |

프롬프트가 해결하는 것은 "**어떻게 시킬 것인가**"의 문제예요. "어떤 정보를 줄 것인가", "어떻게 기억하게 할 것인가"는 프롬프트 너머의 문제예요.

<TryIt>

본인의 업무에서 AI가 잘 안 되는 상황을 하나 떠올려보세요.

```
문제 상황: (예: AI에게 우리 회사 제품 설명을 시켰는데 엉뚱한 내용이 나옴)
한계 유형: (지시 망각 / 환각 / 컨텍스트 부재)
프롬프트로 해결 가능 여부: (O / X / 부분적)
필요한 추가 접근: (예: 제품 정보를 컨텍스트로 제공)
```

</TryIt>

## 6. 트러블슈팅

<Troubleshoot q="10턴이 넘어도 AI가 규칙을 잘 지키는데요?">
모델 성능이 올라가면서 지시 유지력도 좋아지고 있어요. 15턴, 20턴까지 이어가보세요. 또는 규칙과 무관한 주제로 크게 바꿔보면 위반이 더 빨리 나타나요.
</Troubleshoot>

<Troubleshoot q="환각 유도 질문에 AI가 '모르겠다'고 답했어요.">
최근 모델들은 환각 방어가 많이 개선됐어요. 좋은 신호예요. 다만 항상 그런 것은 아니니 다른 없는 논문이나 없는 인물로 시도해보세요. "확실해? 나는 분명히 존재하는 걸로 아는데"라고 유도하면 나타나기도 해요.
</Troubleshoot>

<Troubleshoot q="ChatGPT에서는 규칙을 잘 지키는데 Claude에서는 빨리 잊어요 (또는 반대).">
모델마다 지시 유지력이 다른 건 자연스러워요. 중요한 것은 "모든 모델에 이 한계가 존재한다"는 사실이에요. 정도의 차이일 뿐이에요.
</Troubleshoot>

<Troubleshoot q="컨텍스트를 많이 넣을수록 항상 좋은 건가요?">
아니에요. 관련 없는 정보를 너무 많이 넣으면 오히려 혼란스러워해요. **관련성 높은 정보를 구조화해서** 제공하는 게 중요해요. 양보다 질이에요.
</Troubleshoot>

<Troubleshoot q="환각을 완전히 없앨 방법은 없나요?">
프롬프트만으로는 불가능해요. 검증 가능한 출처를 요구하거나, 외부 데이터를 연결(<Term id="T-RAG" />)하거나, 사람이 검토하는 루프를 추가하면 크게 줄일 수 있어요.
</Troubleshoot>

<Callout type="key">
1. **지시 망각** — 7~10턴을 넘기면 초기 규칙을 잊기 시작해요. 프롬프트만으로는 완전 해결 불가
2. **환각** — 모르는 것을 자신 있게 지어내는 구조적 특성. 버그가 아니라 확률적 생성의 부산물
3. **컨텍스트 부재** — 배경 정보 없이는 일반론뿐. 프롬프트 기법이 아니라 정보 제공이 필요
4. 이 세 한계가 **컨텍스트 엔지니어링이 필요한 이유**예요
</Callout>
