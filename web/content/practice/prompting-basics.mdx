## 준비물

- ChatGPT(무료) 또는 Claude(무료) — 둘 중 하나만 있으면 돼요
- 웹 브라우저
- 결과를 기록할 메모장 또는 노트 앱

## 1. 프롬프트가 뭐길래

<Term id="T-PROMPT" />는 AI에게 보내는 지시문이에요. 식당에서 주문할 때를 생각해보세요. "뭐 맛있는 거 주세요"라고 하면 셰프가 알아서 아무거나 내놓겠죠. "매운 거 빼고, 해산물 파스타, 크림 소스로 해주세요"라고 하면 원하는 음식이 나올 확률이 훨씬 높아요.

AI도 똑같아요. 프롬프트가 모호하면 AI는 그럴듯하지만 원하지 않는 답을 줘요. 좋은 프롬프트에는 세 가지 축이 있어요.

| 축 | 설명 | 식당 비유 |
|---|---|---|
| **맥락(Context)** | 상황·배경·관계 등 작업의 배경 정보 | 알레르기, 취향, 예산, 인원 알려주기 |
| **제약조건(Constraints)** | 지켜야 할 규칙, 포함/제외할 내용 | 맵기 빼고 해산물 위주로 요청 |
| **형식(Format)** | 출력의 구조와 형태 | 코스인지 단품인지 정하기 |

이 세 축을 하나씩 추가하면서 결과가 어떻게 달라지는지 직접 확인해볼게요.

## 2. 실습 — 프롬프트 3단 변환

<Step n={1} title="나쁜 프롬프트로 시도하기">

ChatGPT 또는 Claude를 열고 아래를 그대로 입력하세요.

```
사과 메일 써줘
```

AI가 뭔가를 써줄 거예요. 하지만 실제로 쓸 수 있을까요? 네 가지를 체크해보세요.

- 누구에게 보내는 메일인지 맞나요?
- 어떤 상황의 사과인지 맞나요?
- 메일의 톤이 적절한가요?
- 바로 복사해서 보낼 수 있는 수준인가요?

대부분 하나도 만족하지 못할 거예요. AI는 아무 정보도 받지 못했으니 전부 추측으로 채울 수밖에 없거든요. **결과를 메모장에 복사해두세요.**

</Step>

<Step n={2} title="작업 맥락을 추가해보기">

새 대화를 열고 맥락을 추가해보세요.

```
온라인 쇼핑몰의 CS팀장이 고객에게 보내는 사과 메일을 써줘.
배송이 늦어진 상황이야.
```

Step 1의 결과와 비교해보세요. 맥락이 들어가면 AI는 "누가 누구에게, 왜 쓰는 글인지"를 이해하고 적절한 어투와 구조를 잡아줘요.

하지만 여전히 부족해요. 구체적으로 어떤 상황인지, 어떤 조건을 지켜야 하는지 AI는 모르거든요. 이 결과도 복사해두세요.

</Step>

<Step n={3} title="맥락 + 제약조건 + 형식을 전부 추가하기">

다시 새 대화를 열고, 세 축을 모두 제공해보세요.

```
<context>
발신: 온라인 쇼핑몰 CS팀장
수신: 노트북을 주문한 고객 (이미 1회 항의 전화를 한 상태)
사안: 배송 예정일보다 5일 지연, 원인은 물류 센터 시스템 오류
</context>

<task>
위 상황에서 사과 + 보상안 메일을 작성해주세요.
- 구체적인 보상안(15% 할인 쿠폰)을 포함해주세요
</task>

<format>
- 제목 포함
- 3단 구조: 사과 → 원인 설명 → 보상안
- 300자 내외
- 정중하되 과도하게 비굴하지 않은 톤
</format>
```

구체적인 맥락이 들어가면 AI는 더 이상 추측하지 않아요. 형식이 들어가면 출력 구조까지 예측 가능해져요. XML 태그로 영역을 분리하면 AI가 각 부분의 역할을 명확히 이해해요. 이것이 <Term id="T-STRUCT" />의 기초예요.

</Step>

<Step n={4} title="세 가지 결과를 나란히 비교하기">

메모장에 복사해둔 세 결과를 놓고 표를 직접 채워보세요.

| 평가 항목 | Step 1 | Step 2 | Step 3 |
|---|---|---|---|
| 상황 정확도 | ?/5 | ?/5 | ?/5 |
| 톤 적절성 | ?/5 | ?/5 | ?/5 |
| 바로 사용 가능 여부 | ?/5 | ?/5 | ?/5 |
| 구조/형식 완성도 | ?/5 | ?/5 | ?/5 |
| **총점** | ?/20 | ?/20 | ?/20 |

점수를 매겨보면 패턴이 보여요. 맥락만 추가해도 점수가 오르고, 제약조건과 형식까지 추가하면 크게 뛰어요.

</Step>

<Callout type="key">
AI가 똑똑해져서 결과가 좋아진 게 아니에요. **사람이 정보를 잘 전달해서** 좋아진 거예요. AI의 성능을 끌어올리는 가장 빠른 방법은 모델을 바꾸는 게 아니라 프롬프트를 바꾸는 거예요.
</Callout>

## 3. 내 업무에 적용하기

<TryIt>

아래 세 상황 중 하나를 골라 "맥락 + 제약조건 + 형식" 구조로 프롬프트를 작성해보세요.

- **상황 A — 업무 메일**: 맥락(발신자·수신자·관계·상황) / 제약조건(포함·제외할 내용) / 형식(제목 포함, 단락 수, 톤)
- **상황 B — 보고서 요약**: 맥락(주제·핵심 수치·독자) / 제약조건(원본 수치만 사용, 추측 금지) / 형식(3줄 요약, 핵심 수치, 경어체)
- **상황 C — 아이디어 브레인스토밍**: 맥락(문제·분야·시도한 것) / 제약조건(예산·실현 가능성) / 형식(번호 목록, 장단점 포함)

마음에 들지 않는 부분이 있다면 맥락이나 형식을 수정해서 다시 시도해보세요.

</TryIt>

## 4. 좋은 프롬프트 체크리스트

| 항목 | 확인 |
|---|---|
| 작업 맥락이 충분한가요? | 누가 누구에게, 왜, 어떤 상황에서 필요한 건지 설명했는지 |
| 구체적인 제약조건이 있나요? | 포함/제외할 내용, 지켜야 할 규칙을 명시했는지 |
| 이유(동기)를 함께 제공했나요? | "하지 마" 대신 "이렇게 해, 왜냐하면"으로 지시했는지 |
| 형식을 지정했나요? | 길이·구조·톤 등 출력 형태를 정했는지 |
| 한 번에 하나만 요청했나요? | 여러 작업을 한꺼번에 요청하면 품질이 떨어져요 |

## 5. 자주 하는 실수

**실수 1 — 맥락 없이 막연하게 요청하기.** "SNS 글 써줘"만으로는 부족해요. 어떤 제품인지, 타겟이 누구인지, 어떤 플랫폼인지, 톤은 어떤지를 알려줘야 해요.

**실수 2 — 한 번에 너무 많이 요청하기.** "전략 세우고, 예산도 잡고, 일정도 짜고, 보고서도 써줘." 이러면 모든 항목이 얕아져요. 하나씩 요청하고 결과를 확인한 뒤 다음으로 넘어가세요.

**실수 3 — 형식 지정을 잊기.** AI는 기본적으로 길게 쓰려는 경향이 있어요. "3줄로", "표로", "번호 목록으로"를 지정하지 않으면 불필요하게 긴 답변이 돌아와요.

**실수 4 — AI를 만능으로 기대하기.** 프롬프트를 아무리 잘 써도 AI는 최신 데이터를 모르거나, 사실을 지어내거나, 내부 사정을 알 수 없어요. **프롬프트가 해결하는 것은 전달의 문제이지 AI 능력의 한계가 아니에요.** 이 차이는 <LessonLink id="PR-02" />에서 직접 체험합니다.

## 6. 트러블슈팅

<Troubleshoot q="맥락을 줬는데도 응답이 별로 달라지지 않아요.">
맥락이 아직 추상적일 수 있어요. "마케팅 글 써줘" 대신 "스타트업 B2B SaaS 제품의 인스타그램 캡션을 써줘. 타겟은 20대 개발자, 톤은 캐주얼"처럼 상황·대상·조건을 구체적으로 추가해보세요.
</Troubleshoot>

<Troubleshoot q="프롬프트를 길게 쓰면 AI가 지시를 무시해요.">
프롬프트가 너무 길면 AI가 일부를 놓칠 수 있어요. 핵심 지시는 맨 앞이나 맨 뒤에 배치하세요. 중간에 있는 지시는 무시될 확률이 높아요 — <Term id="T-LIM" /> 현상이에요.
</Troubleshoot>

<Troubleshoot q="같은 프롬프트를 넣었는데 매번 다른 답이 나와요.">
정상이에요. AI는 확률적으로 텍스트를 생성하기 때문에 매번 조금씩 다른 결과가 나와요. 핵심 구조와 내용이 일관되면 정상 작동하는 거예요.
</Troubleshoot>

<Troubleshoot q="ChatGPT와 Claude에서 결과가 다른 이유는 뭔가요?">
모델마다 학습 데이터, <Term id="T-ALIGN" /> 방식, 응답 스타일이 달라요. 자연스러운 현상이고, 프롬프트 구조가 좋으면 어떤 모델에서든 품질이 올라가요.
</Troubleshoot>

<Troubleshoot q="형식을 지정했는데 AI가 안 지켜요.">
형식 지시는 프롬프트의 마지막에 배치하면 더 잘 지켜져요. "반드시 ~형식으로 작성해"처럼 강조하거나, 예시를 한 개 보여주면 효과적이에요.
</Troubleshoot>

<Callout type="key">
1. **맥락**을 제공하면 AI가 추측 대신 정보에 기반해 답해요
2. **제약조건**을 명시하면 범위 안에서 정확하게 작업해요. "하지 마"보다 "이렇게 해 + 이유"가 효과적
3. **형식**을 지정하면 출력 구조가 예측 가능해져요
4. 세 축을 동시에 적용하면 품질이 비약적으로 올라가요
</Callout>
