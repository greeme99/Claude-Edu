## 오늘 만들 결과물

어질러진 폴더 하나가 정리되고, 그 안의 문서에서 뽑아낸 내용이 **표가 들어간 실제 파일**로 같은 폴더에 저장돼요. 명령어는 한 줄도 입력하지 않습니다.

<Callout type="quote">
<LessonLink id="TH-07" />에서 봤듯 Cowork는 Claude Code와 **같은 에이전트 아키텍처**를 터미널 없이 쓰는 표면이에요. 그래서 <LessonLink id="PR-11" />에서 관찰한 **Gather → Act → Verify** 루프가 여기서도 똑같이 돌아요. 다만 대상이 코드베이스가 아니라 여러분의 폴더일 뿐이에요.
</Callout>

## 준비물

- Claude 데스크톱 앱 (macOS 또는 Windows) — 유료 플랜 필요
- 정리해도 괜찮은 **연습용 폴더** 하나 (중요 파일이 없는 곳)
- 그 폴더 안에 파일 10~30개 (PDF·문서·이미지·스프레드시트가 섞여 있으면 좋아요)

<Callout type="warn">
첫 실습은 **반드시 연습용 폴더**에서 하세요. 다운로드 폴더를 복사해 `cowork-practice`라는 이름으로 만들고 그 안에서 시작하는 것을 권합니다. 원본을 건드리지 않는 상태에서 감을 잡는 것이 먼저예요.
</Callout>

## 1. Cowork 켜기

<Step n={1} title="Chat이 아니라 Cowork를 선택해요">

Claude 데스크톱 앱을 열고 메시지 입력창을 보세요. **Chat / Cowork** 를 고르는 자리가 있습니다. Cowork를 선택하세요.

이 한 번의 선택으로 달라지는 것을 미리 정리해둘게요.

| | Chat | Cowork |
|---|---|---|
| 내 파일 | 첨부한 것만 | 연결한 폴더 전체 |
| 결과물 | 채팅창 안의 텍스트 | 실제 파일로 저장 |
| 앱을 닫으면 | 대화가 멈춤 | **세션이 계속 진행** |
| 도구 | 없음 | 커넥터·스킬·브라우저 |

Cowork 세션은 Anthropic 서버에서 실행돼요. 그래서 앱을 닫아도 작업이 계속되고, 데스크톱에서 시작한 일을 모바일에서 확인할 수 있어요.

</Step>

## 2. 폴더 연결

<Step n={2} title="작업할 폴더를 연결해요">

Cowork 세션에서 **폴더 연결**을 선택하고 준비한 연습용 폴더를 고르세요.

여기서 꼭 이해해야 할 원칙이 하나 있어요. **Claude는 연결하지 않은 폴더에는 접근할 수 없어요.** 옆 폴더도, 상위 폴더도 보이지 않습니다. 접근 범위는 여러분이 명시적으로 허용한 만큼이 전부예요.

연결이 되면 먼저 상태를 확인해보세요.

```
이 폴더에 뭐가 들어 있는지 정리해서 보여줘.
파일 유형별 개수, 전체 용량, 가장 오래된 파일과 가장 최근 파일을 알려줘.
아직 아무것도 바꾸지 마.
```

**"아직 아무것도 바꾸지 마"** 를 붙인 이유가 있어요. 이것이 <LessonLink id="PR-11" />에서 배운 **Gather 단계를 명시적으로 요청하는 것**이에요. 큰 작업 전에 전체 그림을 먼저 파악하게 하는 습관이에요.

</Step>

<TryIt>

Claude의 답을 검토해보세요.

1. 파일 개수가 실제와 맞나요? (탐색기에서 직접 세어 비교)
2. 여러분이 몰랐던 파일이 나왔나요?
3. Claude가 어떤 도구를 써서 알아냈는지 보이나요?

</TryIt>

## 3. 승인 모드 이해하기

<Step n={3} title="첫 작업 전에 자율성 수준을 정해요">

Cowork에는 승인 모드가 세 단계 있어요. 첫 작업은 **수동**으로 시작하는 것을 권합니다.

| 모드 | 동작 | 언제 |
|---|---|---|
| **수동(Manual)** | 매 행동 전에 물어봄 | **첫 실습, 되돌리기 어려운 작업** |
| **자동(Auto)** | 스스로 안전성을 점검한 뒤 실행 | 검증 가능한 반복 작업. 사용량을 더 씁니다 |
| **건너뛰기(Skip)** | 자동 점검 없음 | 모든 행동을 완전히 신뢰할 때만 |

여기에 더해 **삭제 보호**가 걸려 있어요. 파일을 영구 삭제하려면 별도의 명시적 허가가 필요합니다. Claude가 마음대로 지우는 일은 일어나지 않아요.

</Step>

<Callout type="key">
<LessonLink id="PR-11" />의 원칙이 그대로예요. **자율성은 검증 가능성에 비례해서** 올리세요. 코드에서 그 기준이 테스트 커버리지였다면, 파일 작업에서는 **"되돌릴 수 있는가"** 입니다. 복사본을 만드는 작업은 자동으로 돌려도 되고, 원본을 덮어쓰는 작업은 수동이 맞아요.
</Callout>

## 4. 첫 작업 — 폴더 정리

<Step n={4} title="파일을 분류하고 정리해요">

수동 모드인 상태에서 요청하세요.

```
이 폴더의 파일을 유형과 주제에 따라 하위 폴더로 정리해줘.

규칙:
- 원본 파일을 삭제하지 말고 이동만 해줘
- 무엇을 어디로 옮길지 계획을 먼저 보여주고, 내 확인을 받은 뒤 실행해줘
- 어느 분류에도 확실히 속하지 않는 파일은 _확인필요 폴더에 따로 모아줘
- 파일 이름은 바꾸지 마
```

Claude가 **계획을 먼저 제시**할 거예요. 이때가 중요한 순간이에요. 계획을 읽고 이상한 분류가 있으면 지금 고치세요.

```
_확인필요로 보낸 것 중에 회의록으로 보이는 건 문서 폴더로 넣어줘.
나머지는 그대로 진행해.
```

승인하면 실제로 파일이 움직여요. 탐색기를 열어 결과를 직접 확인하세요.

</Step>

<TryIt>

정리 결과를 검증해보세요.

1. 파일 총 개수가 정리 전후로 같나요? (없어진 파일이 있으면 안 돼요)
2. `_확인필요` 폴더에 들어간 것들이 정말 애매한 파일인가요?
3. 되돌리고 싶다면? 이렇게 요청해보세요.

```
방금 한 정리를 전부 되돌려서 원래대로 평평하게 만들어줘.
```

**되돌릴 수 있는지 확인하는 것까지가 실습이에요.** 되돌릴 수 없는 작업에는 자동 승인을 걸면 안 된다는 걸 몸으로 아는 게 목적입니다.

</TryIt>

## 5. 두 번째 작업 — 문서에서 뽑아내기

<Step n={5} title="흩어진 문서를 하나의 표로 만들어요">

이번에는 <LessonLink id="PR-03" />에서 한 문서 작업을 **여러 파일을 대상으로** 해볼게요. 폴더에 PDF나 문서가 여러 개 있다고 가정합니다.

```
이 폴더의 PDF와 문서를 전부 읽고 아래 항목을 표로 정리해줘.

추출 항목: 파일명 | 문서 종류 | 작성일(있으면) | 핵심 내용 한 줄 | 등장하는 금액이나 수치

규칙:
- 문서에 실제로 적혀 있는 내용만 써줘. 추측하지 마
- 확인이 안 되는 항목은 "(미확인)"이라고 표시해줘
- 읽을 수 없는 파일이 있으면 이유와 함께 따로 알려줘

결과는 이 폴더에 요약표.xlsx 로 저장해줘.
```

<LessonLink id="PR-01" />의 세 축이 그대로 들어가 있는 게 보이나요? **맥락**(어떤 폴더의 무엇을), **제약조건**(추측 금지, 미확인 표시), **형식**(표 항목과 저장 위치). 표면이 바뀌어도 좋은 프롬프트의 구조는 같아요.

</Step>

<Callout type="key">
여기서 Chat과의 결정적 차이가 드러나요. Chat이라면 채팅창 안에 표가 그려지고, 그걸 엑셀로 옮기는 건 사람의 일이었어요. Cowork는 **수식이 들어간 실제 .xlsx 파일을 폴더에 직접** 만들어요. **"AI의 답을 산출물로 옮겨 적는 시간"이 사라지는 지점**이에요.
</Callout>

<TryIt>

만들어진 파일을 열어보고 검증하세요. <LessonLink id="PR-05" />에서 쓴 체크리스트가 그대로 유효해요.

| 검토 항목 | 확인 |
|---|---|
| 원본 문서에 없는 수치가 들어가 있진 않나요? | <Term id="T-HALL" /> 확인 |
| "(미확인)"이 정직하게 표시되었나요? | |
| 읽지 못한 파일을 숨기지 않고 보고했나요? | |
| 표가 바로 쓸 수 있는 수준인가요? | |

원본 한 건을 골라 직접 열어보고 표의 내용과 대조하세요. **한 건만 대조해도** AI가 성실하게 읽었는지 아닌지 대체로 드러나요.

</TryIt>

## 6. 세션은 클라우드에 있어요

<Step n={6} title="앱을 닫아도 계속되는지 확인해요">

시간이 좀 걸릴 만한 작업을 시켜보세요.

```
이 폴더의 모든 문서를 읽고, 주제별로 묶어서
주제 요약.md 파일을 만들어줘. 각 주제마다 관련 파일 목록도 붙여줘.
```

작업이 진행되는 중에 **모바일 Claude 앱을 열어보세요.** 같은 세션이 그대로 보이고 진행 상황을 확인할 수 있어요. 세션이 기기가 아니라 **계정에 붙어 있기** 때문이에요.

다만 여기에 반드시 알아야 할 제약이 있어요.

</Step>

<Callout type="warn">
**세션은 클라우드에, 파일은 내 컴퓨터에 있어요.**

- 데스크톱 앱을 닫으면 → 세션은 계속 돌지만 **연결된 폴더에는 손이 닿지 않아요**
- 컴퓨터가 잠들면 → 같은 일이 벌어져요
- 웹·모바일에서 로컬 파일을 쓰려면 → **데스크톱 앱이 열려 있어야** 해요

"왜 갑자기 파일을 못 읽지?"의 답은 대부분 여기에 있어요. 로컬 파일을 다루는 긴 작업은 **컴퓨터를 켜둔 채로** 돌리세요.
</Callout>

| 표면 | 로컬 파일 | 내장 브라우저 |
|---|---|---|
| 데스크톱 | 직접 접근 | 사용 가능 |
| 웹 · 모바일 | 데스크톱 앱이 켜져 있을 때만 | 데스크톱 앱이 온라인일 때만 |

## 7. 폴더 지침으로 반복을 줄이기

<LessonLink id="PR-07" />에서 `CLAUDE.md`로 프로젝트 규칙을 고정했던 걸 기억하세요? Cowork에는 같은 역할을 하는 **지침(Instructions)** 이 세 층으로 있어요.

| 층 | 위치 | 범위 |
|---|---|---|
| **전역 지침** | 설정 → Cowork → 전역 지침 (데스크톱) | 모든 세션 |
| **프로젝트 지침** | 프로젝트 우측 패널 | 해당 프로젝트 |
| **조직 지침** | 관리자 설정 | 조직 전체 |

`CLAUDE.md`와 완전히 같은 발상이에요. **매번 설명하지 않아도 되게 만드는 것.** 예를 들어 전역 지침에 이렇게 적어둘 수 있어요.

```
- 응답과 산출물은 한국어로 작성한다
- 파일을 정리할 때 원본을 삭제하지 않고 이동만 한다
- 문서에서 정보를 추출할 때 추측하지 않고, 불확실하면 "(미확인)"으로 표시한다
- 큰 작업은 계획을 먼저 보여주고 승인을 받은 뒤 실행한다
```

<TryIt>

위 네 줄을 전역 지침에 넣고, 새 세션에서 프롬프트에는 그 규칙을 **적지 말고** 같은 작업을 시켜보세요. 규칙이 지켜지나요?

이것이 <LessonLink id="PR-07" />에서 CLAUDE.md 유/무를 비교했던 실험과 정확히 같은 실험이에요.

</TryIt>

## 8. 트러블슈팅

<Troubleshoot q="폴더를 연결했는데 Claude가 파일을 못 찾아요.">
데스크톱 앱이 열려 있고 컴퓨터가 잠들지 않았는지 먼저 확인하세요. 웹이나 모바일에서 작업 중이라면 데스크톱 앱이 켜져 있어야 로컬 파일에 접근할 수 있어요. 그다음 연결한 폴더가 맞는지, 파일이 하위 폴더에 있는지 확인하세요.
</Troubleshoot>

<Troubleshoot q="파일을 지워달라고 했는데 안 지워져요.">
삭제 보호 때문이에요. 영구 삭제에는 별도의 명시적 허가가 필요해요. 안전장치이니 우회하려 하지 말고, 정말 지워야 한다면 요청 시 나오는 확인 절차를 따르세요. 애매하면 `_삭제예정` 폴더로 옮겨두고 나중에 직접 지우는 편이 안전해요.
</Troubleshoot>

<Troubleshoot q="작업이 중간에 멈춘 것 같아요.">
승인 대기 중일 수 있어요. 수동 모드에서는 매 행동 전에 확인을 요청하니 대기 중인 승인이 있는지 보세요. 진짜로 멈췄다면 "어디까지 했고 왜 멈췄는지 알려줘"라고 물어보세요.
</Troubleshoot>

<Troubleshoot q="Chat보다 사용량이 훨씬 빨리 줄어요.">
정상이에요. Cowork는 여러 단계를 자율 실행하기 때문에 일반 채팅보다 훨씬 많은 연산을 써요. 자동 승인 모드는 자체 안전 점검을 추가로 돌기 때문에 더 씁니다. **Chat으로 충분한 일은 Chat에서** 하세요.
</Troubleshoot>

<Troubleshoot q="원본 파일이 바뀔까 봐 불안해요.">
좋은 불안이에요. 세 가지로 대응하세요. ① 연습은 복사본 폴더에서만, ② 프롬프트에 "원본을 수정하지 말고 새 파일로 만들어줘"를 명시, ③ 중요한 폴더는 애초에 연결하지 않기. 연결하지 않은 폴더는 Claude에게 존재하지 않는 것과 같아요.
</Troubleshoot>

<Troubleshoot q="스캔한 PDF를 못 읽는다고 해요.">

</Troubleshoot>

<Callout type="key">
1. Cowork는 **같은 에이전트 루프**를 코드가 아닌 파일·폴더에 적용한 표면이에요
2. **연결하지 않은 폴더에는 접근할 수 없어요** — 접근 범위가 곧 안전 경계
3. **승인 모드 3단계 + 삭제 보호**. 첫 작업은 수동으로, 자율성은 되돌릴 수 있는 만큼만
4. 큰 작업 전에 **"아직 바꾸지 마"로 Gather를 먼저** 시키세요
5. 결과물이 **실제 파일로** 폴더에 저장돼요. 옮겨 적는 시간이 사라져요
6. **세션은 클라우드, 파일은 내 컴퓨터** — 로컬 작업 중에는 데스크톱 앱을 켜두세요
7. **지침(전역·프로젝트·조직)** 은 CLAUDE.md와 같은 역할이에요
