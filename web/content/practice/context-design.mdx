## 준비물

- ChatGPT(무료) 또는 Claude(무료)
- 결과를 나란히 비교할 메모장
- **시간 여유** — 새 대화를 여러 번 열어야 해요

## 1. 컨텍스트 엔지니어링이란

<Term id="T-PE" />은 "어떻게 시킬 것인가"의 문제예요. <Term id="T-CE" />은 "**어떤 정보를 줄 것인가**"의 문제예요.

식당 비유로 다시 생각해볼게요. 프롬프트 엔지니어링은 주문서 작성법이에요. 컨텍스트 엔지니어링은 셰프에게 주는 **식재료 세트**예요. 같은 주문서라도 냉장고에 뭐가 있느냐에 따라 요리가 달라지잖아요.

| 층 | 내용 | 비유 |
|---|---|---|
| **역할 컨텍스트** | AI가 어떤 전문가인지 | 셰프의 전공 |
| **상황 컨텍스트** | 배경·관계·히스토리 | 손님의 알레르기, 취향, 지난 방문 기록 |
| **제약 컨텍스트** | 금지사항·형식·톤 규칙 | 예산, 시간, 재료 제한 |

이론적 배경은 <LessonLink id="TH-03" />에 있어요. 오늘은 이 세 층을 하나씩 추가하면서 결과 변화를 관찰합니다.

## 2. 실습 — 4단계 컨텍스트 실험

오늘의 과제는 **"분기 사업 전략 보고서 작성"** 이에요. 같은 작업을 반복하되, 매번 컨텍스트를 한 층씩 추가합니다.

<Step n={1} title="컨텍스트 없이 작업하기 (레벨 0)">

새 대화를 열고 일부러 아무 배경 정보도 주지 않습니다.

```
2분기 사업 전략 보고서를 작성해줘.
```

결과를 받으면 5점 척도로 평가하세요.

- 우리 회사에 맞는 내용인가? (1~5)
- 실행 가능한 전략인가? (1~5)
- 구체적인 수치가 포함돼 있는가? (1~5)
- 바로 사용할 수 있는 수준인가? (1~5)
- 독창적인 인사이트가 있는가? (1~5)

아마 대부분 2점 이하일 거예요. AI는 "어떤 회사"인지 전혀 모르니 일반론을 늘어놓을 수밖에 없어요. **결과를 메모장에 복사해두세요.**

</Step>

<Step n={2} title="역할 컨텍스트만 추가하기 (레벨 1)">

```
역할: 너는 B2B SaaS 스타트업의 COO야.
이 회사의 주력 제품은 프로젝트 관리 도구이고,
직원 20명, 월 매출 5,000만 원 규모야.

2분기 사업 전략 보고서를 작성해줘.
```

역할 컨텍스트가 들어가면 AI는 "B2B SaaS"와 "스타트업"에 맞는 어휘와 관점을 쓰기 시작해요. 일반론에서 한 단계 구체적인 수준으로 올라가요.

하지만 여전히 부족해요. 현재 상황, 경쟁 환경, 지난 분기 성과 같은 구체적 정보가 없으니 AI가 채울 수 있는 범위에 한계가 있어요.

</Step>

<Step n={3} title="상황 + 관계 + 제약조건 추가하기 (레벨 2)">

```
역할: 너는 B2B SaaS 스타트업 "TaskFlow"의 COO야.

회사 현황:
- 직원: 20명 (개발 10, 마케팅 4, 영업 3, 경영지원 3)
- 월 매출: 5,000만 원 (전분기 대비 +15%)
- 고객: B2B 중소기업 80곳
- MRR: 5,000만 원, ARR: 6억 원
- 현금: 8억 원 (런웨이 약 12개월)

1분기 성과:
- 신규 고객 25곳 유치 (목표 20곳 대비 125%)
- 이탈률 3.5% (전분기 5.2%에서 개선)
- NPS 78점 (전분기 72점에서 상승)
- 주요 성과: 대시보드 기능 출시로 대기업 고객 2곳 확보

과제:
- 경쟁사(Notion, Monday.com)가 한국 시장 진출 강화 중
- 시리즈 A 펀딩을 3분기에 계획 중 (목표 30억 원)
- 개발 인력 채용이 어려워 로드맵 지연 발생

보고서 독자: CEO와 이사회
톤: 데이터 기반, 솔직하되 긍정적
분량: A4 2장

2분기 사업 전략 보고서를 작성해줘.
```

상황 컨텍스트가 들어가면 AI는 **우리 회사의 구체적인 숫자**를 기반으로 전략을 세워요. 경쟁 상황, 재무 상태, 채용 어려움 같은 현실적 제약이 반영돼요.

</Step>

<Step n={4} title="결과 비교표 작성하기">

| 평가 항목 (5점 만점) | 레벨 0 | 레벨 1 | 레벨 2 |
|---|---|---|---|
| 회사 적합도 | ? | ? | ? |
| 실행 가능성 | ? | ? | ? |
| 수치 구체성 | ? | ? | ? |
| 즉시 사용 가능 여부 | ? | ? | ? |
| 독창적 인사이트 | ? | ? | ? |
| **총점** | ?/25 | ?/25 | ?/25 |

컨텍스트가 한 층 추가될 때마다 점수가 뚜렷하게 올라가는 패턴이 보일 거예요.

</Step>

<Callout type="key">
AI의 결과 품질은 **모델 성능보다 제공된 컨텍스트의 질**에 더 크게 좌우돼요. 더 비싼 모델을 쓰는 것보다 더 좋은 컨텍스트를 주는 것이 효과적일 때가 많아요.
</Callout>

## 3. 패턴 1 — 페르소나 + 규칙 + 예시

가장 효과적인 컨텍스트 설계 패턴은 세 요소를 조합하는 거예요.

```
[페르소나]
너는 ~이야. ~한 경험이 있고, ~한 스타일로 일해.

[규칙]
1. 항상 ~해
2. 절대 ~하지 마
3. ~할 때는 ~형식으로

[예시]
좋은 출력 예시:
"~~~~~~~~~"

나쁜 출력 예시:
"~~~~~~~~~"
```

예시를 포함하면 AI가 원하는 스타일을 훨씬 정확하게 따라해요 — <Term id="T-FEW" />의 효과예요. "이런 식으로 써줘"라고 말로 설명하는 것보다 실제 예시를 보여주는 게 훨씬 효과적이에요.

<TryIt>

본인의 업무에 맞는 "페르소나 + 규칙 + 예시" 컨텍스트를 만들어보세요.

- **고객 응대 봇**: CS 전문가 페르소나 + 답변 규칙(길이·톤) + 좋은/나쁜 답변 예시
- **보고서 작성 도우미**: 업계 전문가 페르소나 + 형식 규칙 + 기존 보고서 예시
- **콘텐츠 작성 도우미**: 브랜드 보이스 페르소나 + 글쓰기 규칙 + 기존 콘텐츠 예시

작성한 컨텍스트를 AI에 입력하고, 같은 질문을 컨텍스트 유/무로 비교해보세요.

</TryIt>

## 4. 패턴 2 — 대화 기록 관리

<LessonLink id="PR-02" />에서 대화가 길어지면 AI가 지시를 잊는다는 걸 확인했어요. 대응 전략이 두 가지 있어요.

| 전략 | 방법 | 적합한 상황 |
|---|---|---|
| **새 대화 시작** | 중요 규칙을 첫 메시지에 다시 넣고 새 대화를 시작 | 규칙이 절대 바뀌면 안 되는 경우 |
| **중간 요약 삽입** | 대화 중간에 요약을 받은 뒤, 새 대화에 요약만 넣기 | 긴 대화를 이어가야 하는 경우 |

두 번째 전략을 직접 해볼게요.

```
지금까지 우리가 논의한 내용을 아래 형식으로 요약해줘.

1. 결정된 사항 (번호 목록)
2. 아직 결정되지 않은 사항
3. 다음에 논의할 주제

이 요약은 새 대화에서 컨텍스트로 사용할 거야.
```

AI에게 요약을 만들게 한 뒤, 새 대화를 열어 그 요약을 첫 메시지에 붙여넣으면 돼요. **대화의 핵심만 넘기고 불필요한 잡담은 버리는 셈**이에요. 이것이 <Term id="T-COMPRESS" />의 수동 버전이에요.

## 5. 컨텍스트 설계 체크리스트

| 항목 | 확인 질문 |
|---|---|
| 역할 | AI가 어떤 전문가로 행동해야 하는지 명시했나요? |
| 배경 정보 | 작업에 필요한 회사/프로젝트/상황 정보를 제공했나요? |
| 관계 | 누구를 위한 결과물인지(독자·상사·고객) 알려줬나요? |
| 제약조건 | 하면 안 되는 것, 지켜야 할 규칙을 설정했나요? |
| 형식 | 출력의 구조·길이·톤을 지정했나요? |
| 예시 | 좋은 결과물의 예시를 한 개라도 보여줬나요? |
| 검증 요청 | 확실하지 않은 정보에 대해 표시하도록 요청했나요? |

이 7개 항목을 모두 채우면 대부분의 작업에서 만족스러운 결과를 얻을 수 있어요.

## 6. 트러블슈팅

<Troubleshoot q="컨텍스트를 많이 줬는데도 결과가 별로예요.">
양이 아니라 **관련성**이 중요해요. 작업과 무관한 정보를 많이 넣으면 오히려 혼란스러워해요. "이 작업에 가장 중요한 정보 3가지"만 골라서 제공해보세요.
</Troubleshoot>

<Troubleshoot q="매번 긴 컨텍스트를 입력하기 귀찮아요.">
자주 쓰는 컨텍스트는 템플릿으로 저장해두세요. 이걸 파일 하나로 자동화하는 방법이 <LessonLink id="PR-07" />에서 다루는 <Term id="T-CLAUDEMD" />예요.
</Troubleshoot>

<Troubleshoot q="예시를 넣으면 AI가 예시를 그대로 베끼는 것 같아요.">
예시와 함께 "이 예시의 구조와 톤을 참고하되, 내용은 새롭게 작성해줘"라고 명시하세요. 예시를 2~3개 넣으면 특정 예시를 베끼는 대신 공통 패턴을 학습하는 경향이 있어요.
</Troubleshoot>

<Troubleshoot q="컨텍스트 설계에 시간을 많이 쓰면 AI를 안 쓰는 것보다 오래 걸리지 않나요?">
처음에는 시간이 좀 걸려요. 하지만 템플릿을 한 번 만들어두면 다음부터는 복붙이에요. 보고서를 매달 쓰는 사람이라면, 한 번의 컨텍스트 설계가 12개월의 시간을 절약해줘요.
</Troubleshoot>

<Troubleshoot q="회사 기밀 정보를 컨텍스트로 넣어도 되나요?">
무료 AI는 입력 데이터가 모델 훈련에 사용될 수 있어요. **기밀 정보는 넣지 마세요.** 기밀이 포함된 작업은 엔터프라이즈 플랜을 쓰거나, 민감 정보를 가명으로 바꾼 뒤 입력하세요.
</Troubleshoot>

<Callout type="key">
1. 컨텍스트 엔지니어링은 "**어떤 정보를 줄 것인가**"의 문제. 프롬프트 기법보다 결과에 더 큰 영향
2. 컨텍스트는 **역할 + 상황 + 제약**의 세 층. 한 층 추가마다 품질이 눈에 띄게 상승
3. **페르소나 + 규칙 + 예시** 패턴이 가장 효과적. 특히 예시의 효과가 커요
4. 대화가 길어지면 **중간 요약 후 새 대화 시작**으로 관리
</Callout>
