## 오늘 만들 결과물

프로젝트 폴더에 <Term id="T-CLAUDEMD" /> 파일 하나가 생겨요. 이 파일 하나가 Claude Code의 행동 방식을 완전히 바꿉니다. **신입 직원에게 회사 매뉴얼을 건네는 것**과 같아요. 매뉴얼 없이 일하면 매번 물어봐야 하지만, 매뉴얼이 있으면 스스로 판단하고 움직이거든요.

<Callout type="quote">
<LessonLink id="TH-03" />에서 컨텍스트 엔지니어링을 배웠어요. CLAUDE.md는 그 원리를 **파일 하나로 구현한 것**이에요. Claude Code가 프로젝트를 열 때 자동으로 읽고, 거기 적힌 내용이 모든 대화의 시스템 프롬프트처럼 작동해요.
</Callout>

<Step n={1} title="설치 상태를 확인해요">


버전 번호가 출력되면 설치 완료예요. "command not found"가 나오면 아직 설치가 안 된 거예요.

</Step>

Node.js가 먼저 설치되어 있어야 해요. 없다면 nodejs.org에서 LTS 버전을 설치하세요.

</TryIt>

설치가 확인되면 아무 폴더에서나 실행해보세요.


대화형 인터페이스가 열리면 물어보세요.

`/exit`으로 나오세요.

## 3. CLAUDE.md 작성

<Step n={3} title="CLAUDE.md를 직접 작성해요">

CLAUDE.md는 프로젝트 루트에 위치하는 마크다운 파일이에요. **별도의 설정이나 등록 과정이 필요 없어요.** 파일이 있으면 읽고, 없으면 안 읽어요.

여기에는 크게 세 가지를 적습니다.

**1) 빌드 명령어** — Claude가 코드를 수정한 후 테스트를 돌려보거나 빌드가 깨지지 않았는지 확인할 때 씁니다.

```markdown
# Practice Todo App

## 빌드 & 실행
- 실행: `python src/main.py`
- 테스트: `pytest tests/ -v`
- 린트: `ruff check src/`
- 포맷: `ruff format src/`
```

**2) 코드 스타일 규칙** — 모호하게 적으면 모호하게 따르고, 구체적으로 적으면 정확하게 따라요.

```markdown
## 코드 스타일
- 언어: Python 3.11+
- 타입 힌트: 모든 함수에 필수
- Docstring: Google 스타일, 한글로 작성
- 변수명: snake_case, 의미가 명확한 영어
- 주석: 한글로 작성, "왜"를 설명 (무엇을 하는지는 코드로)
- 에러 처리: 구체적 예외 타입 사용 (bare except 금지)
- import 순서: 표준 라이브러리 → 서드파티 → 로컬 (빈 줄로 구분)
```

**3) 프로젝트 구조** — Claude가 "어디에 코드를 넣어야 하지?"라고 고민하지 않게 해줘요.

```markdown
## 프로젝트 구조
practice-todo-app/
+-- src/
|   +-- main.py      # 엔트리포인트, CLI 인터페이스
|   +-- models.py    # 데이터 모델 (Todo, TodoList)
|   +-- utils.py     # 유틸리티 함수
+-- tests/
|   +-- test_main.py # 테스트
+-- docs/            # 문서
+-- CLAUDE.md        # Claude Code 설정
+-- README.md        # 프로젝트 소개

## 규칙
- 새 기능 추가 시 반드시 테스트도 함께 작성
- 한 함수는 30줄을 넘기지 않음
- 전역 변수 사용 금지
```

세 부분을 합치면 완성이에요.

</Step>

<Callout type="quote">
CLAUDE.md는 "완벽해야 한다"는 부담을 가질 필요가 없어요. 처음에는 간단하게 시작하고, 프로젝트가 진행되면서 점점 추가하면 돼요.
</Callout>

### CLAUDE.md 작성 팁

| 원칙 | 설명 |
|---|---|
| **구체적으로** | "좋은 코드를 작성해" 대신 "타입 힌트 필수, Google 스타일 docstring" |
| **짧게** | 너무 길면 오히려 효과가 떨어져요. 핵심만 간결하게 |
| **실행 가능하게** | 빌드 명령어는 복사해서 바로 실행할 수 있는 형태로 |
| **점진적으로** | 처음부터 완벽할 필요 없어요. 필요할 때마다 추가 |
| **예시 포함** | 코드 스타일은 좋은 예시와 나쁜 예시를 함께 적으면 효과적 |

## 5. CLAUDE.md의 계층 구조

CLAUDE.md는 세 가지 위치에 둘 수 있고, 각각 다른 범위로 작동해요.

| 위치 | 범위 | 용도 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 모든 프로젝트 | 개인 선호 (언어, 문체 등) |
| 프로젝트 루트 `CLAUDE.md` | 해당 프로젝트 | 빌드, 스타일, 구조 (팀 공유) |
| 하위 폴더 `CLAUDE.md` | 해당 폴더 하위 | 모듈별 특수 규칙 |

여러 위치에 있으면 **모두 읽고, 충돌하는 규칙이 있으면 더 가까운(하위) 파일이 우선**해요. 팀 전체의 규칙은 루트에, 특정 모듈의 규칙은 하위 폴더에 분리할 수 있어요.

<TryIt>

홈 디렉토리에 개인용 CLAUDE.md를 만들어보세요.

```bash
mkdir -p ~/.claude
```

`~/.claude/CLAUDE.md`에 아래 내용을 적으세요.

```markdown
# 개인 설정
- 응답 언어: 한국어
- 코드 주석: 한글
- 설명은 간결하게, 코드는 상세하게
```

이후 어떤 프로젝트에서 Claude Code를 실행하든 이 설정이 기본으로 적용돼요.

</TryIt>

## 7. 트러블슈팅

<Troubleshoot q="claude 명령어가 실행되지 않아요.">
Node.js 18 이상이 설치되어 있는지 `node --version`으로 확인하세요. npm 전역 설치 경로가 PATH에 포함되어 있는지도 `npm config get prefix`로 확인하세요.
</Troubleshoot>

<Troubleshoot q="CLAUDE.md를 만들었는데 Claude가 무시하는 것 같아요.">
파일 이름이 정확히 `CLAUDE.md`인지 확인하세요. **대소문자가 중요해요.** `claude.md`나 `Claude.md`가 아닌 `CLAUDE.md`여야 해요. 또한 파일이 프로젝트 루트에 있는지 확인하세요.
</Troubleshoot>

<Troubleshoot q="Claude가 CLAUDE.md의 규칙을 일부만 따라요.">
너무 길거나 규칙이 모호하면 일부를 놓칠 수 있어요. 규칙을 줄이고, 가장 중요한 것부터 위에 배치하세요. 구체적인 예시를 함께 적으면 준수율이 올라가요.
</Troubleshoot>

<Troubleshoot q="기존 프로젝트에 CLAUDE.md를 추가하고 싶은데 뭘 적어야 할지 모르겠어요.">
Claude Code에게 물어보세요. `이 프로젝트를 분석하고 CLAUDE.md를 만들어줘`라고 요청하면 프로젝트 구조를 파악해서 초안을 작성해줘요. 거기서 수정하면 훨씬 빨라요.
</Troubleshoot>

<Troubleshoot q="팀원들과 CLAUDE.md를 공유하고 싶어요.">
일반 파일이니 Git에 커밋하면 돼요. 프로젝트 루트의 CLAUDE.md는 팀 공유용, `~/.claude/CLAUDE.md`는 개인 설정용으로 분리하세요.
</Troubleshoot>
