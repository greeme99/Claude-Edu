> **차시 순번과 ID의 분리 (v1.1 정정)**
> 초안에서 "기존 순번을 건드리지 않는다"고 쓰고 사이트맵에는 Cowork를 6번째에 배치해 모순이 있었다. 아래로 확정한다.
>
> | 차시 | ID (불변) | seq (표시 순서) |
> |---|---|---|
> | AI는 어떻게 여기까지 왔나 | `TH-01` | 1 |
> | AI는 왜 틀리고 왜 맞는가 | `TH-02` | 2 |
> | 프롬프트의 한계와 컨텍스트 엔지니어링 | `TH-03` | 3 |
> | 하네스 | `TH-04` | 4 |
> | MCP에서 Skills까지 | `TH-05` | 5 |
> | **Cowork: 세 번째 표면** [신규] | **`TH-07`** | **6** |
> | AI 시대에 무엇을 준비해야 하는가 | `TH-06` | **7** |
>
> Cowork는 MCP·Skills 다음에 오는 것이 교육 흐름상 맞고, 마무리 차시는 마지막에 있어야 한다. 그래서 **표시 순서(`seq`)는 재배열하되 ID는 부여 순서대로 고정**한다. 상호참조는 전부 ID로 걸리므로 재배열이 링크를 깨뜨리지 않는다. **ID와 seq를 분리한 스키마(DR-01)가 존재하는 이유가 바로 이것이다.**
>
> 실습 트랙은 13·14를 뒤에 붙이므로 재배열이 없다 (`PR-13`, `PR-14` / seq 13, 14).
>
> 후속 작업: 기존 이론 6차시 본문의 "6차시(이번 차시)" 표현은 Phase 01 정합성 수정에서 순번 비의존 표현으로 교체한다.

## 3. URL 설계

| 패턴 | 예시 | 규칙 |
|---|---|---|
| 트랙 목록 | `/theory`, `/practice` | 고정 |
| 차시 상세 | `/theory/{slug}` | slug는 영문 소문자·하이픈. 한글 미사용 |
| 차시 내 섹션 | `/theory/{slug}#section-id` | 본문 h2에서 자동 생성 |
| 용어 항목 | `/terms#{term-id}` | 개별 페이지를 만들지 않음 |
| 템플릿 항목 | `/templates#{template-id}` | 개별 페이지를 만들지 않음 |
| 검색 | `/search?q={query}` | 쿼리 파라미터. 공유 가능 |

**설계 판단 — 용어에 개별 페이지를 주지 않는 이유**
용어 70개에 각각 페이지를 만들면 얇은 콘텐츠 70장이 생긴다. 한 줄 정의만 있는 페이지는 SEO상 불리하고 사용자에게도 이동 비용만 발생시킨다. 용어사전 단일 페이지 + 앵커가 규모에 맞다. 용어별 해설이 문단 수준으로 길어지면 그때 페이지로 승격한다.

## 5. 콘텐츠 관계 모델

```
                    ┌──────────────┐
                    │    LESSON    │
                    │  (차시 21개)  │
                    │   id: TH/PR  │
                    └──┬───┬───┬───┘
        참조당함(refs)  │   │   │  소유
        ┌───────────────┘   │   └────────────┐
        │                   │                │
   ┌────▼─────┐      ┌──────▼──────┐   ┌─────▼─────┐
   │   TERM   │      │   LESSON    │   │   QUIZ    │
   │ 용어 70  │      │  (상호참조)  │   │  문항 70  │
   └────┬─────┘      │ LessonLink  │   └───────────┘
        │            └─────────────┘
   본문에서 마킹
        │
   ┌────▼──────────────┐
   │  차시 본문 (MDX)   │
   └───────────────────┘

   ┌───────────┐        ┌────────────┐
   │ TEMPLATE  │        │  RESOURCE  │
   │ 템플릿 25 │        │  자료 40   │
   └───────────┘        └────────────┘
   트랙 비종속 횡단 자원. 차시에서 선택적으로 링크
```

| 관계 | 카디널리티 | 무결성 규칙 |
|---|---|---|
| LESSON ↔ TERM | N:M | `terms.refs`의 모든 ID가 실재해야 함 (V-07) |
| LESSON → QUIZ | 1:N | `quiz.lesson_id`가 실재해야 함 (V-08) |
| LESSON → LESSON | N:M | `<LessonLink>` 대상이 실재해야 함 (V-05) |
| LESSON → TEMPLATE | N:M (선택) | 끊어져도 빌드는 통과. 경고만 |
| LESSON → RESOURCE | 없음 | 자료실은 독립 |

## 7. 사용자 흐름

### UF-01 · 교육 중 용어 확인 (UC-01, 모바일)
```
검색 아이콘 → 키워드 입력 → 용어 결과 선택 → 용어사전 앵커
                                    │
                                    └→ 관련 차시 링크 → 차시 상세
```
**설계 목표:** 3단계, 30초 이내

### UF-02 · 본문 독서 중 용어 확인 (UC-03) — 주 시나리오
```
차시 상세 → 용어에 호버/탭 → 팝오버에서 정의 확인 → 팝오버 닫고 독서 계속
                                    │
                                    └→ (더 알고 싶으면) 용어사전
```
**설계 목표:** 페이지 이탈 없이 해결. 이것이 PDF 대비 핵심 개선점

### UF-03 · 템플릿 찾아 쓰기 (UC-02)
```
템플릿 → 카테고리 필터 → 항목 펼침 → 복사 → (사이트 이탈, 실제 업무에서 사용)
```
**설계 목표:** 이탈이 정상 종료다. 체류시간을 늘리려 하지 않는다

### UF-04 · 커리큘럼 조망 후 학습 (UC-04)
```
홈 → 커리큘럼 → 트랙 선택 → 차시 선택 → 완독 → 다음 차시
                                              │
                                              └→ 대응 실습 차시
```

### UF-05 · 검색 유입 후 탐색 (UC-07)
```
외부 검색엔진 → 차시 상세(중간 진입) → 학습 목표로 맥락 파악
                      │
                      ├→ 용어 툴팁으로 모르는 개념 해결
                      ├→ 이전 차시로 배경 보충
                      └→ 커리큘럼으로 전체 조망
```
**설계 목표:** 단독 진입해도 길을 잃지 않음 (P-4)

### UF-06 · 운영자 콘텐츠 갱신 (UC-05)
```
구글시트 열기 → 행 수정 → 저장 → [GAS onChange, 5분 디바운스]
    → Vercel Deploy Hook → 빌드 → 검증 게이트
                                      ├─ 통과 → 배포 → 사이트 반영
                                      └─ 실패 → 이전 배포 유지 + 실패 알림
```
