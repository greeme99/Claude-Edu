## 1. 데이터 명세

기능 정의에 앞서 데이터 구조를 확정한다. F-08과 F-10이 이 명세를 강제한다.

### 1.1 MDX 차시 파일

경로: `content/theory/{slug}.mdx`, `content/practice/{slug}.mdx`

프론트매터:

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ✅ | 불변 고유 ID. 예: `TH-03`, `PR-07`. **한 번 부여하면 변경 금지** |
| `track` | enum | ✅ | `theory` \| `practice` |
| `seq` | number | ✅ | 트랙 내 표시 순서. 차시 삽입 시 재조정 가능 (ID는 불변) |
| `title` | string | ✅ | 차시 제목 |
| `slug` | string | ✅ | URL 경로. 한 번 정하면 변경 금지 (DR-04) |
| `summary` | string | ✅ | 목록·검색·OG 설명에 사용. 1~2문장 |
| `goals` | string[] | ✅ | 학습 목표 |
| `keyQuestion` | string | | 핵심 질문 (이론 차시) |
| `prerequisites` | string[] | | 선행 차시 ID |
| `updatedAt` | date | ✅ | 최종 갱신일 |
| `status` | enum | ✅ | `draft` \| `review` \| `published`. `published`만 사이트에 노출 |

본문에서 사용 가능한 컴포넌트:

| 컴포넌트 | 용도 |
|---|---|
| `<Callout type="key\|warn\|quote">` | 핵심 정리 박스, 주의, 인용 |
| `<Step n="1" title="...">` | 실습 차시의 단계 |
| `<TryIt>` | "직접 해보기" 블록 |
| `<Troubleshoot q="..." a="..." />` | 트러블슈팅 Q&A |
| `<Checklist items={[...]} />` | 실습 체크리스트 |
| `<KeyTerms ids={["...","..."]} />` | 핵심 용어 — 시트에서 정의를 끌어와 렌더 |
| `<Quiz lessonId="..." />` | 확인 문제 — 시트에서 문항을 끌어와 렌더 |
| `<LessonLink id="TH-05" />` | 차시 상호참조. **순번 하드코딩 금지** |

### 1.2 Google Sheets 탭

공통 규칙:
- 1행은 헤더. 빌드 스크립트는 **열 위치가 아닌 헤더명으로** 열을 찾는다
- 필수 열 누락 시 빌드 실패 (F-10)
- 빈 행은 무시. `id`가 비어 있으면 그 행 전체를 무시

**`lessons`** — 차시 목차의 보조 메타 (본문 프론트매터가 우선, 이 탭은 목록 순서·상태 관리용)

| 열 | 필수 | 설명 |
|---|---|---|
| `id` | ✅ | 차시 ID. MDX 프론트매터와 일치해야 함 |
| `track` | ✅ | `theory` \| `practice` |
| `seq` | ✅ | 표시 순서 |
| `title` | ✅ | 제목 (MDX와 불일치 시 빌드 경고) |
| `slug` | ✅ | URL 경로 |
| `status` | ✅ | `draft` \| `review` \| `published` |
| `updated_at` | ✅ | 갱신일 (YYYY-MM-DD) |

| 열 | 필수 | 설명 |
|---|---|---|

## 2. 기능 상세

### F-01 · 차시 열람

**목적** 사용자가 차시 본문을 원본과 동일한 정보량으로 읽는다.

**동작**
1. 사용자가 차시 URL에 진입한다
2. 시스템은 정적 생성된 HTML을 즉시 반환한다
3. 화면 구성: 트랙·차시 번호 → 제목 → 학습 목표 → (핵심 질문) → 본문 → 핵심 정리 → 핵심 용어 → 확인 문제 → 이전/다음 → 갱신일

**규칙**
| ID | 규칙 |
|---|---|
| R-01-1 | `status`가 `published`가 아닌 차시는 페이지를 생성하지 않는다 |
| R-01-2 | 본문 내 등록 용어는 F-05 툴팁 대상으로 자동 마킹한다 |
| R-01-3 | 표는 폭이 넘칠 때 자체 컨테이너에서 가로 스크롤한다. 페이지 본문은 가로 스크롤하지 않는다 |
| R-01-4 | 코드블록은 복사 버튼을 제공한다 |
| R-01-5 | 본문 h2·h3에서 목차를 자동 생성한다 (데스크톱: 우측 고정, 모바일: 상단 접힘) |
| R-01-6 | 갱신일은 `updatedAt` 기준으로 "2026년 9월 9일 갱신" 형식으로 표시한다 |

**예외**
| 상황 | 처리 |
|---|---|
| 존재하지 않는 slug | 404 페이지. 커리큘럼 목차로 유도 |
| `<KeyTerms>`가 미등록 용어 ID 참조 | **빌드 실패** (F-10) |
| `<Quiz>`에 해당 차시 문항이 0건 | 확인 문제 섹션 자체를 렌더하지 않음 (빈 섹션 금지) |
| 이전/다음 차시가 없음 (첫·마지막) | 해당 버튼 비활성 표시. 링크 미생성 |

### F-02 · 커리큘럼 내비게이션

**목적** 전체 구조를 조망하고 원하는 차시로 이동한다.

**동작**
1. 커리큘럼 페이지에서 이론·실습 두 트랙을 나란히 제시한다
2. 각 차시 카드에 번호·제목·학습 목표 요약·갱신일을 표시한다
3. 헤더의 전역 내비게이션에서 어느 페이지에서든 커리큘럼·용어사전·템플릿·자료실로 이동 가능하다

**규칙**
| ID | 규칙 |
|---|---|
| R-02-1 | 차시 표시 순서는 `seq` 오름차순을 따른다 |
| R-02-2 | `<LessonLink id="...">`는 빌드 시 해당 차시의 실제 제목과 URL로 치환된다. 본문에 차시 번호를 하드코딩하지 않는다 |
| R-02-3 | 이론과 실습의 대응 관계(예: 이론 4차시 ↔ 실습 7차시)가 정의된 경우 상호 링크를 노출한다 |

**예외**
| 상황 | 처리 |
|---|---|
| `<LessonLink>`가 존재하지 않는 ID 참조 | **빌드 실패** (F-10) — 원본 PDF의 깨진 참조 7건이 재발하지 않도록 하는 장치 |
| `seq` 중복 | 빌드 경고 후 `id` 사전순으로 안정 정렬 |

### F-03 · 통합 검색

**목적** 키워드로 차시·용어·템플릿을 한 번에 찾는다.

**동작**
1. 헤더 검색 버튼 또는 `/` 단축키로 검색을 연다
2. 입력과 동시에 결과가 유형별로 그룹화되어 표시된다 (용어 → 차시 → 템플릿 순)
3. 결과 선택 시 해당 페이지로 이동한다. 차시 결과는 매칭된 섹션 앵커로 이동한다

**규칙**
| ID | 규칙 |
|---|---|
| R-03-1 | 검색 인덱스는 빌드 시점에 생성한다. 런타임 서버 조회는 없다 |
| R-03-2 | 한국어 부분 일치를 지원한다. 형태소 분석 대신 2-gram 인덱스를 사용한다 |
| R-03-3 | 영어 원어로도 검색된다 ("context engineering" → 컨텍스트 엔지니어링) |
| R-03-4 | 검색 대상: 차시 제목·요약·본문 텍스트, 용어 한/영/정의, 템플릿 제목·본문 |
| R-03-5 | 결과에 매칭 문맥을 발췌해 표시하고 매칭어를 강조한다 |
| R-03-6 | 유형별 최대 5건씩 표시하고, 초과 시 "더 보기"를 제공한다 |

**예외**
| 상황 | 처리 |
|---|---|
| 결과 0건 | "'{키워드}'에 대한 결과가 없습니다" + 용어사전·커리큘럼 링크 제시 |
| 1글자 입력 | 검색 실행하지 않음. 안내 문구 표시 |
| 인덱스 로드 실패 | 검색 UI에 오류 안내. 나머지 페이지 기능은 정상 유지 |

### F-04 · 용어사전

**목적** 용어 70여 개를 카테고리별로 열람하고 필요한 항목을 찾는다.

**동작**
1. 용어사전 페이지에서 전체 용어를 카테고리별로 그룹화해 표시한다
2. 카테고리 필터와 텍스트 필터를 제공한다
3. 각 용어 항목은 한국어·영어·정의·관련 차시 링크를 포함한다

**규칙**
| ID | 규칙 |
|---|---|
| R-04-1 | 카테고리 5종은 원본 부록 A의 분류를 따른다 |
| R-04-2 | 한국어 가나다순으로 정렬한다 |
| R-04-3 | 각 용어는 `#{id}` 앵커를 가지며 툴팁에서 직접 연결된다 |
| R-04-4 | `refs`의 각 차시 ID는 차시 제목이 표시된 링크로 렌더한다 |

**예외**
| 상황 | 처리 |
|---|---|
| `refs`가 비어 있음 | 관련 차시 영역을 렌더하지 않는다 |
| `refs`가 미등록 차시 ID 참조 | **빌드 실패** (DR-02, F-10) |
| `en`이 비어 있음 | 영어 표기 영역 생략 |

### F-05 · 용어 툴팁

**목적** 본문 독서 흐름을 끊지 않고 용어 정의를 확인한다. **PDF 대비 가장 큰 개선점.**

**동작**
1. 빌드 시 본문 텍스트를 스캔해 등록 용어와 일치하는 표현을 마킹한다
2. 사용자가 마킹된 용어에 호버(데스크톱) 또는 탭(모바일)하면 정의 팝오버가 열린다
3. 팝오버는 한국어·영어·정의·"용어사전에서 보기" 링크를 포함한다

**규칙**
| ID | 규칙 |
|---|---|
| R-05-1 | 매칭은 `ko`와 `aliases`를 대상으로 한다 |
| R-05-2 | **한 차시 안에서 동일 용어는 첫 등장 1회만 마킹한다.** 본문이 링크 밭이 되는 것을 방지 |
| R-05-3 | 제목(h1~h3), 코드블록, 이미 링크인 텍스트, 표 헤더는 마킹 대상에서 제외한다 |
| R-05-4 | 마킹 표시는 밑줄 점선을 사용한다. 색상만으로 구분하지 않는다 (NFR-05) |
| R-05-5 | 키보드 포커스로도 팝오버가 열려야 한다 (NFR-06) |
| R-05-6 | 모바일에서는 탭으로 열리고, 외부 탭 또는 닫기 버튼으로 닫힌다 |
| R-05-7 | 긴 표현을 우선 매칭한다 ("컨텍스트 엔지니어링"이 "컨텍스트"보다 우선) |

**예외**
| 상황 | 처리 |
|---|---|
| 해당 차시 자신이 그 용어의 주 설명 차시 | 마킹하되 팝오버의 "용어사전에서 보기"만 제공 (자기 페이지 링크 회피) |
| 용어가 문장 부호에 붙어 있음 | 용어 부분만 마킹 |
| 팝오버가 화면 밖으로 나감 | 위치를 자동 반전한다 |

### F-06 · 프롬프트 템플릿 라이브러리

**목적** 템플릿 25종을 찾아 바로 복사해 쓴다.

**동작**
1. 템플릿 목록에서 카테고리·난이도로 필터링한다
2. 항목을 열면 본문·사용법·예상 결과가 표시된다
3. 복사 버튼으로 본문을 클립보드에 복사한다

**규칙**
| ID | 규칙 |
|---|---|
| R-06-1 | 복사 대상은 `body`만이다. 사용법·예상 결과는 복사하지 않는다 |
| R-06-2 | 복사 성공 시 "복사했습니다" 피드백을 2초간 표시한다 |
| R-06-3 | 난이도는 ★ 1~3개로 표시한다 |
| R-06-4 | `body` 안의 `[대괄호]` 자리표시자는 시각적으로 강조해 교체가 필요함을 알린다 |
| R-06-5 | 고급 기법(E 카테고리)은 `source`의 원논문 출처를 함께 표시한다 |

**예외**
| 상황 | 처리 |
|---|---|
| 클립보드 API 미지원·권한 거부 | 본문을 자동 선택 상태로 만들고 "직접 복사하세요" 안내 |
| 필터 결과 0건 | "조건에 맞는 템플릿이 없습니다" + 필터 초기화 버튼 |

### F-08 · 콘텐츠 빌드 파이프라인

**목적** 두 콘텐츠 소스를 빌드 시점에 정적 데이터로 합친다.

**동작**
1. 빌드 시작 시 Google Sheets의 5개 탭을 "웹에 게시" CSV로 조회한다
2. 헤더명 기준으로 열을 매핑하고 타입을 검증한다 (F-10)
3. 정규화된 JSON을 `.content-cache/`에 생성한다
4. 성공 시 이 JSON을 `content-snapshot/`에 커밋 대상으로 갱신한다
5. MDX를 컴파일하고 JSON 데이터를 주입해 페이지를 정적 생성한다
6. 검색 인덱스를 생성한다

**규칙**
| ID | 규칙 |
|---|---|
| R-08-1 | 런타임에는 Google Sheets를 호출하지 않는다 (C-02) |
| R-08-2 | 자격증명을 사용하지 않는다. 공개 CSV URL만 사용한다 (C-04) |
| R-08-3 | 시트 조회는 탭당 1회, 총 5회를 넘지 않는다 |
| R-08-4 | 조회 타임아웃은 탭당 15초. 2회까지 재시도한다 |

**예외**
| 상황 | 처리 |
|---|---|
| 시트 조회 실패 (네트워크·구글 장애) | `content-snapshot/`의 마지막 성공 스냅샷으로 빌드를 계속하고, 빌드 로그에 경고를 남긴다 (FR-20) |
| 스냅샷도 없음 (최초 빌드) | 빌드 실패. 원인을 명시 |
| CSV에 개행이 포함된 셀 | RFC 4180 준수 파서 사용. 자체 split 금지 |

### F-09 · 자동 재배포

**목적** 콘텐츠 수정이 사람 개입 없이 사이트에 반영된다.

**동작**

| 경로 | 트리거 | 흐름 |
|---|---|---|
| 시트 수정 | GAS `onChange` | 변경 감지 → 디바운스 → Vercel Deploy Hook 호출 → 재빌드 |
| MDX 수정 | `git push` | Vercel Git 연동 → 재빌드 |

**규칙**
| ID | 규칙 |
|---|---|
| R-09-1 | GAS 트리거는 **5분 디바운스**를 적용한다. 연속 편집이 매번 배포를 유발하면 안 된다 |
| R-09-2 | Deploy Hook URL은 GAS 스크립트 속성에 저장한다. 시트 셀에 두지 않는다 |
| R-09-3 | 배포 소요 목표는 5분 이내다 (NFR-17) |
| R-09-4 | 빌드 실패 시 **이전 배포가 그대로 유지된다.** 깨진 사이트가 노출되지 않는다 |

**예외**
| 상황 | 처리 |
|---|---|
| Deploy Hook 호출 실패 | GAS가 3회 재시도 후 운영자에게 메일 알림 |
| 빌드 실패 | Vercel이 실패 알림. 운영 사이트는 직전 성공 버전 유지 |
| 연속 편집 | 디바운스 창 안의 변경을 1회 배포로 병합 |

---

### F-10 · 빌드 검증 게이트

**목적** 잘못된 콘텐츠가 배포되는 것을 원천 차단한다. **이 프로젝트에서 가장 중요한 안전장치.**

**동작** 빌드 중 아래 검사를 순차 수행하고, `fail` 등급이 하나라도 걸리면 빌드를 중단한다.

| 검사 ID | 검사 내용 | 등급 |
|---|---|---|
| V-01 | 시트 각 탭의 필수 열이 헤더에 존재하는가 | fail |
| V-02 | 필수 열의 값이 비어 있지 않은가 | fail |
| V-03 | `enum` 필드 값이 허용 목록에 있는가 (`track`, `status`, `category`, `type`) | fail |
| V-04 | `id`가 탭 내에서 유일한가 | fail |
| V-05 | `<LessonLink>`가 참조하는 차시 ID가 실재하는가 | fail |
| V-06 | `<KeyTerms>`가 참조하는 용어 ID가 실재하는가 | fail |
| V-07 | `terms.refs`의 차시 ID가 실재하는가 | fail |
| V-08 | `quiz.lesson_id`의 차시 ID가 실재하는가 | fail |
| V-09 | 본문의 내부 링크(`/theory/...`, `/practice/...`)가 실재 경로인가 | fail |
| V-10 | MDX 프론트매터 필수 필드가 모두 있는가 | fail |
| V-11 | MDX `title`과 `lessons` 탭 `title`이 일치하는가 | warn |
| V-12 | `seq`가 트랙 내에서 중복되는가 | warn |
| V-13 | `resources.url`이 비어 있는가 | warn |
| V-14 | `resources.checked_at`이 180일 초과 경과했는가 | warn |
| V-15 | 어떤 차시에서도 참조되지 않는 용어가 있는가 | info |

**규칙**
| ID | 규칙 |
|---|---|
| R-10-1 | `fail` 발생 시 위반 항목을 **전부** 나열한 뒤 종료한다. 첫 오류에서 멈추지 않는다 |
| R-10-2 | 오류 메시지는 탭명·행 번호·열명·기대값을 포함한다 |
| R-10-3 | 검증은 CI와 로컬 빌드에서 동일하게 동작한다 |

**예외**
| 상황 | 처리 |
|---|---|
| `warn`만 존재 | 빌드 계속. 로그에 요약 출력 |
| 스냅샷 fallback 중 | 검증은 스냅샷 데이터에 대해 동일하게 수행한다 |

## 3. 기능 간 의존 관계

```
F-08 콘텐츠 빌드 ──> F-10 검증 게이트 ──> (통과) ──> 페이지 생성
   │                                              │
   │                                              ├─> F-01 차시 열람
   │                                              ├─> F-04 용어사전
   │                                              ├─> F-06 템플릿
   │                                              └─> F-07 자료실
   │
   └─> 검색 인덱스 생성 ──> F-03 통합 검색

F-01 ──(본문 스캔)──> F-05 용어 툴팁 ──(링크)──> F-04 용어사전
F-02 내비게이션은 모든 페이지에 상주
F-09 자동 재배포는 F-08을 트리거
F-11 공통 UI는 전 화면에 적용
```

**구현 순서 제약:** F-08 → F-10 → F-01 → F-02 → F-04 → F-05 → F-03 → F-06 → F-07.
F-05(툴팁)는 F-04(용어 데이터)가 없으면 만들 수 없고, F-03(검색)은 모든 콘텐츠가 확정된 뒤에 인덱싱해야 한다.
